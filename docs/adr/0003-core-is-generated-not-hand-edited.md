# ADR-0003: core/*.md is generated from active principle practices, never hand-edited

Status: accepted

Issue: (none)
Date: 2026-09-23

## Context

The always-loaded core (ADR-0002) is the single highest-leverage file in this repository: every rule in it reaches every writing moment, unconditionally, for anyone who pastes it. If a maintainer could add a line to `core/core.ja.md` directly, that line would carry the same weight as a fully source-backed practice without ever having gone through `frontmatter-schema`'s evidence requirements, `self-check-resolves`, or `core-budget`'s size limit.

## Decision

`core/core.ja.md` and `core/core.en.md` are generated by `pnpm gen` (`scripts/gen.mjs`'s `renderCore`) from every `status: active`, `scope: principle` practice that carries a `core: {section, order}` field. A maintainer edits a practice's frontmatter and body to change the core; they never edit `core/*.md` directly. `generated-fresh` fails the build if the file on disk does not match what `renderCore` produces.

A section with zero qualifying practices is omitted from the rendered file entirely, rather than left as an empty heading.

## Consequences

Adding, removing, or reordering a core rule is exactly as disciplined as adding, removing, or reordering any other active practice — same schema, same evidence bar, same `pnpm gen` step. The cost is indirection: a maintainer cannot quickly patch a typo in the core's wording without also touching the source practice file, but that is the point — the core's wording is a bilingual `rule` field a downstream consumer also reads verbatim, so a "quick" core-only edit would silently desync the two.
